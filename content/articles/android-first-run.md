## 本文教的是哪个 Clash 手机版

本文只针对 **Clash Meta for Android（CMFA）**，项目为 [MetaCubeX/ClashMetaForAndroid](https://github.com/MetaCubeX/ClashMetaForAndroid)。它与 FlClash、桌面 Clash Verge Rev 的界面不同，不应混用按钮位置。iPhone 不能安装本文所说的 APK。

2026-09-28 核对项目 README、发行页面、简体中文界面资源与 Android VPN 文档。本文是资料与源码核对后的操作指南，尚未在实体 Android 设备上完成安装、真实订阅和网络测试；菜单名称以安装版本为准。

准备三项资料：手机 Android 版本及支持的 ABI、所选 CMFA 版本、服务方提供的 Clash/Mihomo 配置地址。订阅链接通常含账户令牌，截图或求助前需要遮挡。

## 第一步：选 APK，不选源码或桌面文件

从[开发者 Releases](https://github.com/MetaCubeX/ClashMetaForAndroid/releases)打开具体发行，检查更新说明及 Assets。README 当前写明最低 Android 5.0、推荐 Android 7.0 及以上，并列出四类架构；具体发行如果提出更高要求，以该发行要求为准。

| 附件的架构标记 | 对应条件 | 常见误选 |
| --- | --- | --- |
| arm64-v8a | 支持 64 位 ARM ABI 的系统 | 仅凭 CPU 型号判断；部分设备系统只支持 32 位应用 |
| armeabi-v7a | 支持 32 位 ARM ABI 的系统 | 在只接受 64 位应用的设备上尝试安装 |
| x86 / x86_64 | 对应 Intel 架构环境或模拟器 | 把它当作普通 ARM 手机安装包 |

先查设备厂商规格和系统支持情况。熟悉 ADB 的用户可执行 `adb shell getprop ro.product.cpu.abilist` 查看系统报告的 ABI 列表；不要为了运行这一条命令在不可信电脑上长期保留调试授权。

下载 `.apk` 文件。Source code ZIP/TAR 是源码，不是安装包；文件名相近也不能把其他项目 APK 当成 CMFA。不要根据文件大小或“通用高速版”宣传判断架构。

## 第二步：安装与两种权限分开处理

安装 APK 时，系统可能要求允许当前浏览器或文件管理器“安装未知应用”。核对来源后，仅授予正在使用的安装入口；安装完成可收回该权限。提示签名不一致时，不要直接卸载旧版丢掉配置，先检查新旧包是否同一项目和发行渠道。

**安装权限与 VPN 连接授权不是一回事。** 前者允许安装应用，后者允许应用建立系统 VPN 接管路径。Android 官方说明首次启动 VPN 会显示系统连接请求；同一用户或工作资料中只能有一个活跃 VPN 服务，另一个 VPN 或本地 VPN 型过滤应用可能造成冲突。[Android VPN 说明](https://developer.android.com/develop/connectivity/vpn)

## 第三步：导入并激活配置

1. 打开 CMFA 的“配置”页面，使用创建配置入口，选择“从 URL 导入”。这些名称来自项目当前[简体中文界面资源](https://github.com/MetaCubeX/ClashMetaForAndroid/blob/main/design/src/main/res/values-zh/strings.xml)，不保证每个历史版本布局相同。
2. 填入便于识别的配置名称与完整订阅 URL。不要填登录页、付款页或教程网址；拥有 YAML 文件时用“从文件导入”，不要把网页改扩展名后导入。
3. 保存并等待下载、解析完成。记录第一条错误，不连续刷新掩盖状态。
4. 回到配置列表，选择刚导入的条目，确认它处于激活状态。列表里“有一个配置”不等于“当前正使用它”。

订阅更新完成却没有节点时，核对服务方导出的格式以及配置引用的提供商文件是否下载成功，不先假设账户已过期。

## 第四步：启动、选择策略并验证

返回主界面启动服务，确认系统 VPN 请求显示的是本次安装的客户端。进入“代理”页面，找到配置提供的策略组，选择一个明确节点；组名由配置决定，不存在对所有订阅统一的组名。

初次验收保留规则模式，暂不同时修改 DNS、访问控制和多项覆写。打开你准备验证的目标页面，再检查日志或连接信息。记录以下内容：

| 观察点 | 应记录什么 | 不能直接推断什么 |
| --- | --- | --- |
| 配置 | 当前激活名称、更新时间 | 更新成功不代表节点可连接 |
| 系统 | VPN 是否指向 CMFA | VPN 图标不代表目标网站成功 |
| 策略 | 选中组、节点或 DIRECT | 页面打开不一定经过远端节点 |
| 请求 | 时间、目标、错误或规则信息 | 一次请求不代表所有应用可用 |

分别测试一个已知正常的直连目标和一个按你的规则应走代理的目标。规则把某目标分到 DIRECT 时，应记录为直连结果，不能把它当作远端节点速度证明。第一次成功后再测试 Wi-Fi 与移动数据切换，每次只改变一个条件。

## 出问题时，从哪一步倒查

| 现象 | 先检查 | 暂时不要做 |
| --- | --- | --- |
| APK 无法安装 | ABI、系统版本、包完整性、签名/版本冲突 | 反复下载来源不明的同名包 |
| 导入返回 HTML 或 404 | URL 是否为真实配置入口、是否经过登录跳转 | 把网页另存为 YAML |
| YAML 解析报错 | 保存错误行号，核对服务方导出格式 | 同时改 DNS 和节点 |
| VPN 启动后很快断开 | 其他 VPN、系统提示、客户端日志 | 仅凭断开判定订阅失效 |
| 只有某个应用不通 | 访问控制、目标规则、该应用自身网络设置 | 直接重置全机网络 |
| 熄屏后中断 | 中断时间、后台限制、VPN 是否仍运行 | 默认所有机型都用同一保活设置 |

更多下载和解析错误可参考[订阅导入排查](/articles/import-subscription/)，其中桌面接管部分不应直接套到 Android。

## 停止也算首次使用的一部分

从 CMFA 正常停止服务，在 Android VPN 设置确认连接已停止，然后检查日常网络。若启用了“始终开启 VPN”或“无 VPN 时阻止连接”，停止后可能仍被系统阻止直连，应先核对原有设置和用途，而不是连续卸载重装。

保留配置备份和版本号后再升级。向开发者反馈时提供设备系统、客户端版本、具体步骤、时间及脱敏日志；不公开完整订阅地址。
