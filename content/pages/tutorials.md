第一次使用 Clash，可以按“选客户端 → 装软件 → 导入配置 → 启动连接 → 验证 → 排错”的顺序完成。客户端是运行配置的工具，订阅提供节点与规则，两者需要分别准备。以下说明共通流程，按钮名称以所选客户端版本为准。

## 第一步：按设备选择客户端

Windows 电脑从 [Clash 电脑版下载](/downloads/windows/)开始；安卓手机从 [Clash 安卓下载](/downloads/android/)开始。Mac、Linux 和 iOS 用户进入[软件下载中心](/downloads/)筛选平台。优先核对操作系统、CPU 架构、维护状态和项目原始发布页，不仅凭软件名字或标题中的“官网”判断。

## 第二步：下载并安装对应包

进入开发者 Releases，阅读发行说明并在 Assets 下载设备对应的安装包。Source code 是源代码，不是普通用户安装文件。安卓安装 APK；Windows 根据架构选择安装程序。软件要求的权限应结合文档理解，不为解决未知错误一次性关闭所有系统防护。

安装完成后应能打开客户端主界面；这一阶段还不要求节点可用。若软件本身打不开，先解决系统要求、架构和安装依赖，避免同时修改订阅造成混淆。

## 第三步：导入并启用订阅配置

从服务方获取兼容配置链接，在客户端“配置/订阅”中新增 URL 或导入本地文件。保存后执行更新并启用这份配置。不同客户端展示节点的时机不同：Clash Meta for Android 需启动服务后才显示代理入口。网页登录地址与订阅地址不是同一个东西。

**这一阶段的完成标准：** 配置拉取和解析成功、当前配置已选中；启动后再检查预期节点。拉取成功不代表节点已经连通。遇到 401、403、404 或 YAML 解析错误，先读[订阅错误分阶段排查](/articles/subscription-errors/)，不要反复更换客户端。详细步骤见[订阅导入教程](/articles/import-subscription/)。

## 第四步：选择模式并启动

初次设置一般先用规则模式，由配置中的规则决定直连或代理。全局模式可用于短暂对照测试，直连模式用于观察不经过代理的情况；三者区别见[模式选择指南](/articles/rule-global-direct/)。按客户端界面启动流量接管，并进入代理页面选择节点：

- Windows：先启用系统代理，测试遵循系统代理的浏览器；有需要再依据文档设置 TUN。
- Android：确认系统 VPN 连接授权，检查是否被其他 VPN 应用替换。操作示例见 [Clash Meta for Android 首次运行](/articles/android-first-run/)。
- 其他系统：参照客户端开发者文档完成权限与接管设置，不照搬另一平台的开关名称。

## 第五步：用三个检查确认是否可用

| 检查项 | 具体操作 | 能说明什么 |
| --- | --- | --- |
| 目标页面 | 打开你实际需要访问的网页，刷新一次 | 此页面在当前网络、节点和时间下可访问 |
| 规则与连接 | 查看客户端连接记录，核对域名、代理组与规则 | 请求是否按预期进入客户端及命中规则 |
| 直连对照 | 访问一个常用直连站点，检查规则命中与访问情况 | 日常直连是否受影响 |

只显示延迟不等于下载速度，也不能证明流媒体解锁或所有应用均走代理。需要比较速度时先读[延迟与速度的区别](/articles/latency-speed/)。一次测试只改变一个变量，记录时间、客户端、模式和现象，更容易找到原因。

## 第六步：按故障发生的位置排查

1. **无法安装：** 回到平台下载页，检查架构、系统版本与包完整性。
2. **无法拉取订阅：** 查看 HTTP 错误码，检查订阅有效期、链接完整性与网络；不要公开链接中的令牌。
3. **能拉取但不能解析：** 核对配置格式和客户端内核支持情况。
4. **有节点但连接失败：** 先测试本地网络和一个节点，再查看服务方状态与日志。
5. **浏览器可用但某应用不通：** 检查流量接管范围、应用分流和规则，而不是先重装软件。
6. **退出后网络异常：** 检查遗留系统代理或 VPN 状态，恢复直连后再逐步启用。
